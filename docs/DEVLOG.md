## 00:53 · 读活动规则

WorkBuddy「1024 造物挑战」的规则页是前端动态渲染的，直接抓 HTML 只能拿到一个转圈加载的空壳。

处理方法：从页面里找到 `window.__PUBLISH_BOOTSTRAP__` 变量，里面写着真实内容的静态托管地址，顺着这个地址抓到 164 KB 的正文页，把内联脚本里的规则原文全部提取出来。

拿到的关键信息：

| 项 | 内容 | 对开发的影响 |
|---|---|---|
| 评分权重 | 创意 35 / 完成度 40 / 体验 25 / 社媒加分 30 | 完成度权重最高，宁可小而全，不要大而半成品 |
| 投稿截止 | 11-01 23:59 | 从 10-23 算只剩 9 天 |
| 必交材料 | 1-3 张截图 + **可打开的体验链接** | 必须能发布成公开网址 |
| 硬红线 | 算命、占卜、塔罗、八字、星盘类一律取消评奖 | 任何带「预测命运」色彩的功能都不能碰 |

4. 单文件纯前端是最稳的形态，五分之三都是。

结论：避开教育、情绪打卡、比价、待办记账、打 bug 类小游戏。要做视觉冲击强、评审愿意多点两下的东西。

## 01:02 · 调研参考游戏

### 《弓箭手大作战》（Arrow.io 类）

拆出来的三个可复用机制：

1. **虚拟摇杆走位 + 角色自动朝最近目标射击**。玩家不需要瞄准，所有操作围绕走位。这把复杂度从「手眼协调」转到「决策」，对非核心玩家友好。
2. **升级时从随机技能里三选一**，技能分四类：武器种类、武器效果、属性加成、特殊技能。武器是变量，属性是常量。
3. **武器体系分层**：激光穿墙、地刺留场、炸弹范围、镰刀近战，每把的打法逻辑完全不同。

### 《吸血鬼幸存者》

三个可复用机制：

1. 击杀掉经验宝石 → 拾取 → 升级 → 三选一。成长节奏由拾取驱动，不是由击杀驱动，所以玩家会主动往怪物密集处走。
2. 武器满级 + 对应被动满级 + 黄金宝箱 = 超武进化。这是「后期不无聊」的核心设计。
3. 怪物从四周持续刷新，密度随时间提升，压力来自数量而不是单体强度。

### 融合方案

取弓箭手的「走位 + 自动索敌」降低操作门槛，取幸存者的「经验 → 三选一 → 超武」作为成长曲线，再加用户要求的宝箱和背包。

## 01:04 · 技术选型

| 选项 | 判断 |
|---|---|
| Three.js（选定） | 单文件可交付，无构建步骤，改完刷新即生效，核心 150 KB |
| Unity WebGL | 空项目 8-11 MB，评审打开要等 |
| Godot Web | 空项目 5-9 MB，还需要 COOP/COEP 跨域头，托管方不一定给 |
| 纯 Canvas 2D 伪 3D | 不符合「3D 游戏」的要求 |

Three.js 用 r150 的 UMD 版本（`three.min.js`），因为 r155 之后官方移除了 UMD 构建。

CDN 挂两个源，主源失败时自动切备用：

```html
<script src="https://unpkg.com/three@0.150.1/build/three.min.js"></script>
<script>window.THREE||document.write('<script src="https://cdn.jsdelivr.net/npm/three@0.150.1/build/three.min.js"><\/script>');</script>
```

## 01:06 - 01:15 · 写代码

分成三段写，每段写完做语法检查，避免一次性写两千行出一堆错。

| 段落 | 内容 |
|---|---|
| 第一段 | HTML 结构、全部 CSS、渲染器初始化、卡通材质工厂、程序化贴图、场景搭建、相机、屏幕特效、音效合成 |
| 第二段 | 实例池工具、粒子、冲击波、玩家模型、4 种敌人、BOSS、子弹池、经验宝石、宝箱 |
| 第三段 | 6 把武器定义、被动定义、开火逻辑、升级卡池、宝箱开箱、背包渲染、波次与刷怪、输入处理、HUD、主循环、流程控制 |

几个刻意的技术决定：

**全部用程序化几何**。玩家、敌人、宝箱、围墙没有一个外部模型文件，全部是 `IcosahedronGeometry`、`ConeGeometry`、`TorusGeometry` 现场拼的。原因：评审打开时不会因为资源加载失败看到白屏。

**全部走 InstancedMesh 池**。同屏 170 个敌人、300 发子弹，如果每个都是独立 Mesh 就是 470 个 draw call，核显必卡。用实例化把敌人压到每类 2 个 draw call（本体 + 描边），子弹压到 3 个。

**音效用 Web Audio 现场合成**。射击是方波下滑，命中是噪声爆发，升级是上行琶音，全部由代码生成，不加载任何音频文件。

**卡通着色不用后处理**。通常做描边要接 EffectComposer 做边缘检测，但那要额外加载三个脚本模块。改用背面外壳外扩：同一份几何再画一遍，用 `BackSide` 材质，放大 1.15 倍，形成黑边。成本低，风格更接近手绘。

## 01:18 · 修 bug

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 页面完全不响应，所有按钮无效 | HTML 里漏了 `#stick` 摇杆元素，脚本取 `querySelector('.base')` 拿到 null，整个初始化函数中断 | 补上元素 |
| 2 | 地板、光斑纹理全部丢失，画面一片死紫 | 贴图工具函数返回的是 canvas 的 2D context，不是 canvas 本身，`CanvasTexture` 拿到 context 取不到宽高 | 改成返回 canvas，另外取 context |
| 3 | 纹理上传报 `texSubImage2D Overload resolution failed` | 色阶贴图只有 3 像素宽，单通道字节数不满足 4 字节对齐 | 改成 4 像素宽，并设 `unpackAlignment = 1` |
| 4 | BOSS 出场后画面永久白屏 | 闪白效果只有累加没有衰减，一旦触发就再也不会消失 | 主循环里加衰减 |
| 5 | 连续升级时游戏卡死，无法继续 | 升级处理完之后没有把状态切回游戏，下一张卡的定时器检查状态时直接返回 | 先切状态再排下一张卡 |

修完之后全流程跑通：开始 → 移动 → 击杀 → 升级三选一 → 开宝箱 → 背包 → BOSS → 结算，零报错。

## 01:42 · 数值改造

### 先诊断

算了下实际的数值，问题很清楚：

| 数值 | 第 1 波 | 第 10 波 | 倍数 |
|---|---|---|---|
| 敌人血量倍率 | 1.00 | 4.06 | 4.1x |
| 敌人伤害 | 固定 | 固定 | **1.0x** |
| 玩家可达 DPS | 15 | 500+ | **30x 以上** |

两个致命问题：

1. **敌人伤害完全不成长**。玩家血量上限 240，敌人打 7-16 点，无论打到第几波都是这个数。所以玩家死不了。
2. **环绕镰的 DPS 失控**。冷却写的是 0.05 秒，意思是每秒触发 34 次，每次对范围内所有敌人造成 42% 伤害。算下来单目标每秒 513 点，还是 AOE。比单体的激光还高 2 倍，所有武器在它面前没有存在意义。

### 依据

查到的公开方法论，三条：

1. **TTK（击杀耗时）标准**：普通杂兵 2-5 秒，精英 15-30 秒，BOSS 2-5 分钟。TTK 定游戏节奏，太长变枯燥，太短没决策。
2. **锯齿（sawtooth）难度曲线**：每段起点略低于玩家强度给呼吸空间，段中爬升追平，BOSS 超出 10-20%，下一段回落再起步。难度要有峰谷，不能是一条平滑直线。
3. **线性递增 + 阶梯跳跃**：每波线性小涨，每若干个波次额外跳一档。纯线性会「第三波突然打不动」，纯指数会后期崩塌。

还有一条负面清单：敌人血量指数增长配玩家伤害线性增长，落差会无限扩大。反过来玩家成长远超敌人，就是我们现在的情况。

### 改法

敌人血量放弃线性，改成按波次查表，表本身按锯齿设计：

| 波次 | 血量 | 伤害 | 备注 |
|---|---|---|---|
| 1 | 1.00 | 1.00 | 呼吸区 |
| 2 | 1.12 | 1.02 | |
| 3 | 1.38 | 1.16 | 台阶：尖刺兽入场 |
| 4 | 1.52 | 1.20 | |
| 5 | 1.92 | 1.34 | 尖峰：BOSS |
| 6 | 1.66 | 1.38 | 回落 13%，台阶：投掷手入场 |
| 7 | 1.86 | 1.44 | |
| 8 | 2.32 | 1.58 | 台阶：肥球成群 |
| 9 | 2.68 | 1.72 | |
| 10 | 3.35 | 1.92 | 尖峰：最终 BOSS |

波内再线性加 6%（血量）和 5%（伤害），避免整波一个强度。

三个配套改动：

- **环绕镰冷却 0.05 → 0.50 秒**，单次伤害从 42% 提到 100%。DPS 从 513 降到约 180，仍是强力 AOE，但不再碾压一切。
- **敌人伤害接曲线**，第 10 波是 1.92 倍再加波内递增。玩家 240 血，被碰 5-6 次就得走位。
- **加精英怪**。第 3 波起按概率出现，血量 5.5 倍、伤害 1.55 倍、体型 1.32 倍、经验 6 倍，脚下一圈旋转的黄色光环。这是曲线上的小尖峰，也是宝箱的稳定来源。

## 01:44 · 升级系统重做

用户指出的「后期全加血」，在《吸血鬼幸存者》里的解法叫 Limit Break：所有武器和被动满级后，不再给金币或鸡腿这类垃圾选项，转为给武器叠加无限升级。

照这个思路加了两层：

**超武进化**。武器满 5 级 + 指定被动到 3 级，进化成完全不同的形态：

| 武器 | 需要 | 进化成 | 效果 |
|---|---|---|---|
| 爆裂弓 | 攻速 | 箭雨 | 12 发扇形，全穿透 |
| 穿透激光 | 攻击 | 湮灭射线 | 4 束，持续 1.35 秒 |
| 环绕镰 | 移速 | 血月斩 | 6 刃，范围 +60%，命中回血 |
| 抛掷炸弹 | 暴击 | 陨石雨 | 6 颗，爆炸半径 +50% |
| 回旋镖 | 磁力 | 无限回旋 | 4 枚，穿透 + 追踪 |
| 地刺 | 生命 | 荆棘领域 | 5 片，毒池扩大 50% |

**极限突破**。满级武器可以无限叠层，每层 +8% 伤害。这样即使全部内容都满了，选项池也永远不为空。

另外加了**重掷**，每局 3 次，不满意可以重摇三张卡。

原来那个「池子空了塞三个加血」的兜底逻辑删掉了，改成：血量低于 45% 时，用一张治疗替掉第三张卡。有代价，不是白送。

## 尚未验证

诚实记录，这几项没测过：

1. 真实显卡帧率。测试环境是软件渲染，能跑通不代表流畅。
2. 触屏摇杆在真机的手感。
3. 新数值曲线的实际体感。曲线是按公开方法推的，但没经过真人试玩，第 3 波到第 5 波的爬升幅度可能需要回调。
4. 超武进化的实际强度。6 个形态的参数是估的，可能出现某个进化太强或太弱。
