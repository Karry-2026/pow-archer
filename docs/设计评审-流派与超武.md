## 一、流派为什么没有特色

### 1.1 代码里的事实

6 个被动全部是**全局乘区**：

```js
atk   攻击强化   所有伤害 +14%/级
aspd  攻速狂热   全部武器冷却 ×(1-12%/级)
move  疾风之靴   移动速度 +6%/级
hp    铁壁之心   生命上限 +18/级
magnet磁力场     拾取范围 +30%/级
crit  致命一击   暴击率 +7%/级
```

再看卡池：

```js
shuffle(opts);          // 全部候选打乱
out = 前 3 张;           // 均匀随机，没有任何权重
```

**结论：这 6 个被动对 6 把武器的作用完全相同。** 拿"攻击强化"和拿"攻速狂热"，对弓、激光、镰刀、炸弹的收益是一样的。所以玩家的最优策略天然就是"哪个都不亏，来什么点什么"——这不是玩家的问题，是系统没有提供取舍。

### 1.2 你给的两分流，和代码里的机制对不上

你分的：
- 近战流：地刺、回旋镖
- 远程流：炸弹、激光、箭雨

但按实际机制：

| 武器 | 实际机制 | 该归到哪 |
|---|---|---|
| 环绕镰 | 绕身旋转的持续伤害圈 | **贴身**（最典型的近战，你的列表里漏了它） |
| 地刺 | 沿走位在地面留陷阱 | **贴身/阵地** |
| 炸弹 | 抛出后落地范围爆炸 | 投掷（中距，不是"远程"） |
| 回旋镖 | 飞出再飞回，双向命中 | 投掷（它是弹道，不是近战） |
| 穿透激光 | 直线贯穿 | 射线 |
| 爆裂弓 | 扇形散射 | 射线 |

**两分流会把"投掷"和"射线"混成一类，但这两类的打法完全不同**（投掷要算提前量、射线要站桩输出）。分成三条线才有辨识度：

- **贴身线**：环绕镰 + 地刺 → 奖励"往怪堆里钻"
- **投掷线**：炸弹 + 回旋镖 → 奖励"绕圈拉扯、卡距离"
- **射线线**：穿透激光 + 爆裂弓 → 奖励"站定、找直线"

### 1.3 业界参照：Brotato 是怎么做"必须有取舍"的

Brotato 是全行业把"流派代价"做得最硬的一个，机制拆开看只有四条：

1. **伤害属性按流派分开**：Melee Damage / Ranged Damage / Elemental / Engineering 是四个独立属性。近战武器只吃近战伤害，远程只吃远程伤害。
2. **混着点 = 两套都半吊子**。这是它故意的：一把武器没有对应属性支撑，到第 8 波就是"挠痒棒"。
3. **武器带职业标签，同职业叠套装加成**（15 个职业）。6 把同职业的套装加成远大于 6 把混装。
4. **商店有 15% 概率刷到"你已有职业"的武器**。这是关键的软引导：不强制，但会把你往一条路上推。

> 出处：Brotato 官方 Wiki / 公开攻略整理。伤害减免也是公开公式（护甲每点 -6.66% 伤害）。

对照我们：**一条都没有**。没有分离属性、没有职业标签、没有加权刷池，所以"乱加点"是必然结果。

### 1.4 改造方案（三档，从轻到重）

**方案 A（最轻，只动卡池权重）**
- 已拥有武器的升级卡权重 ×2.0
- 已投 ≥2 点的被动权重 ×1.6
- 第 4 把武器只在第 8 波后出现（现状保留）
- 效果：卡池自然收敛，但没增加"取舍"，只是减少随机感
- 开发量：小（只改 `buildChoices` 的权重表）
- 我的评价：**不够**。权重只能让玩家"更顺"，不能让两条路"不一样"

**方案 B（推荐）：流派属性 + 卡池权重**
- 6 个被动重组为 **3 个流派属性 + 3 个通用属性**

| 新属性 | 只作用于 | 每级 | 满级 |
|---|---|---|---|
| 近战精通 | 环绕镰、地刺 | 该流派伤害 +18% | +90% |
| 投掷精通 | 炸弹、回旋镖 | 该流派伤害 +18% | +90% |
| 射击精通 | 穿透激光、爆裂弓 | 该流派伤害 +18% | +90% |
| 疾风之靴 | 全局 | 移速 +6% | +30% |
| 铁壁之心 | 全局 | 生命 +18 | +90 |
| 磁力场 | 全局 | 拾取 +30% | +150% |

- 攻速怎么办？**攻速是唯一保留的全局输出乘区**，但降档到 +6%/级（原 +12%）。理由：攻速对"数量型武器"（弓、飞镖、炸弹）收益远高于"单发型"（激光、镰刀），它本身就在暗中偏袒某几条线，不能让它太强。
- 暴击同理：并入"致命一击"保留，但只影响**单发伤害**，对多弹武器收益高——这也是偏袒，所以降档到 +5%/级。

- 卡池权重：已有武器 ×2.0，匹配流派 ×1.6，其余 ×1.0
- 超武前置从"任意被动 3 级"改成"**对应流派属性 3 级**"，让超武成为流派的终点确认

**为什么这样就有特色了**：拿"投掷精通"却不带炸弹和回旋镖，就是白拿。玩家必须在第 3–5 波就决定"我这条线走哪"，而且**中途改道要付代价**（已投的等级没法回收）。

**方案 C（最重）：武器槽从 4 降到 3**
- 槽位越少，"带哪三把"越像构筑决策
- 代价：容错变低，且现有 BOSS 的 DPS 派生要重算
- 我的判断：可以做，但应该等方案 B 跑一轮看体感，不要一次改两件事

## 二、炸弹震屏：为什么会"震 4 下"

### 2.1 代码事实

```js
function shake(amt){ camShake = Math.max(camShake, amt); }
// ...
camShake *= Math.pow(0.0025, dt);   // 半衰期约 0.12 秒
```

每颗炸弹落地各调一次 `shake(0.3)`。因为用的是 `Math.max`：

- 第 1 颗：camShake = 0.3
- 0.12 秒后衰减到 0.15
- 第 2 颗：`max(0.15, 0.3)` = **0.3，重新顶满**

所以 4 颗炸弹 = 4 次独立的满强度脉冲，每次都被"重置"。加上 4 颗炸弹的落点不同（`life` 是 0.42–0.62 随机），震动在时间上是错开的，**画面就是一抽一抽地抖 4 下**。

### 2.2 正确做法：trauma 模型（GDC 公开公式）

Squirrel Eiserloh 在 GDC《Math for Game Programmers: Juicing Your Cameras With Math》里给的模型，现在被 Bevy 官方示例、Godot 社区方案、大量独立游戏照搬：

```
trauma = min(trauma + amount, 1.0)   // 累加，但有上限
trauma -= decay * dt                  // 线性衰减（不是指数）
shakeAmount = trauma ^ 2              // 平方，让小震动更轻、大震动更猛
offset = maxOffset * shakeAmount * noise(t)
```

关键差别：

| | 现在的 `max()` | trauma 累加 |
|---|---|---|
| 4 颗炸弹同时炸 | 仍然是 1 次 0.3 的震动 | 0.2×4 = 0.8，**1 次强震** |
| 4 颗炸弹错开 0.15s | **4 次独立脉冲（抽搐）** | 连续累积到 0.8 再平滑回落，**1 次长震** |
| 上限 | 无（大事件会盖住小事件，不能叠加） | 1.0，防止叠加过头 |

**所以修法不是"加冷却"，而是把 `max` 改成"累加 + 封顶 + 平方"**。单次爆炸从 0.3 降到 0.18–0.22，4 颗连炸自然累积到 0.8 左右，然后一次连续衰减——这就是"无论丢几个炸弹只震一下"的正确形态，而且不会丢失打击感。

另外：GDC 那场还建议 3D 里**主要用旋转震动而不是位移震动**（位移容易让相机穿进墙）。我们的相机是固定俯角，位移安全，但建议保留一点 Z 轴旋转（±0.6°），震动会更"有重量"。

## 三、BOSS 时长：12 秒 → 30–45 秒

### 3.1 现状

| | 目标秒数 | 实测 |
|---|---|---|
| 第 5 波 裂口巨兽 | 12 | 6.5 – 16.6 秒（8 样本，均值 13.0） |
| 第 10 波 千手墨神 | 20 | 16.4 – 21.9 秒（4 样本，均值 19.4） |

用户的期待 30–45 秒，落在公开的数值规范区间内：

> TapTap《游戏数值设计规范》：前期 Boss 30–60 秒，中期 Boss 60–120 秒。
> 中文 ARPG 怪物设计：BOSS 90–300 秒（含共斗类），小怪 3–10 秒，精英 10–30 秒。

对一个单局 5–6 分钟的割草游戏，第 5 波（局中）用 30 秒、第 10 波（终局）用 45 秒是合理的：两场合计 75 秒，占全局约 22%。

### 3.2 但不要靠"加血"拉长

血量直接翻 2.5 倍会变成"血条海绵"：玩家做的事没变，只是重复更久。**用"无效输出窗口"来拉长**，同时给战斗加节拍：

| 手段 | 时长 | 效果 |
|---|---|---|
| 转阶段（血量 60% 触发） | 4–6 秒 | BOSS 无敌、瞬移、召唤 6 只小兵，玩家清兵或调整位置 |
| 狂暴护盾（血量 30% 触发） | 3–4 秒 | 出现护盾需打破（独立血条），破盾后 2 秒易伤 |
| 招式硬直回报 | 每次 1.2 秒 | 打中弱点后 BOSS 硬直，玩家获得输出窗口 |

这样"血量 = 有效 DPS × (目标秒数 × 0.7)"，血条数字只涨 1.7 倍，但墙钟时长到 30–45 秒，且中间有 2–3 个事件节点。

### 3.3 具体数值

| | 目标墙钟 | 有效输出窗口占比 | 血量（按当前 DPS 估算） |
|---|---|---|---|
| 第 5 波 | 32 秒 | 72% | 约 10,400（现 5,412） |
| 第 10 波 | 45 秒 | 72% | 约 77,000（现 47,800） |

血量仍是 `实时 DPS × 有效秒数` 派生，不写死。**顺带要改 HP 条的数字格式**（10.4 万 / 7.7 万），否则 5 位数挤不下。

> 参照：TwinFlame 的"战斗时长 = HP / DPS，先定时长再解血量"，并强调**用真实玩家 DPS 估计，不要用完美手法**——我们现在的 `currentBossDPS()` 已经是这个口径。

## 四、远程怪没有预警（比你说的更严重）

### 4.1 代码事实

```js
} else if(key === 'thrower'){
  if(e.cd <= 0 && d < 17){
    e.cd = 2.8;
    spawnEBullet(e.x, e.z, nx*11, nz*11, e.dmg);   // 零前摇，直接生成
    SFX.shoot();                                    // ← 用的是玩家的开枪音效
  }
}
```

三个问题：

1. **零前摇**：冷却一到立刻生成子弹，投掷手身上没有任何动作、没有光圈、没有指向线。玩家只能等子弹飞到眼前才知道。
2. **敌弹是黄色**（`COS.yel = #ffe600`）。而同屏还有：金色经验球（`#ffd24a`）、金色爆炸冲击波、金色暴击火花。**危险色和收益色撞了**——这正是你说的"一坨颜色混到一起"。
3. **音效共用**：敌人开枪和玩家开枪是同一个 `SFX.shoot()`，玩家分不清"是我在打还是我在挨打"。

### 4.2 业界规则（三条，都有出处）

**规则一：危险色要独占一个色系，不能和战利品共用。**

> Boghog《Bullet Hell Shmup 101》：传统黄色和橙色子弹会与爆炸、金色物品重叠，所以弹幕游戏大多用红、粉、紫。
> 网易《像素飞行射击设计参考》：子弹要高饱和高亮度，与背景拉开；描边几乎必备；可与发射者同色，方便判断来源。

**规则二：世界压暗、威胁提亮，靠明度差读弹。**

> Hades 可读性研究（Haaga-Helia 论文，逐帧量化）：Hades 里 90–95% 的弹幕集中在"白 / 粉 / 白偏粉"这个窄色带；而场景底色 RGB 普遍低于 70–80。危险靠"世界暗、威胁亮"来读，不是靠色相区分。

**规则三：预警窗口约 800ms，但玩家只看最后 200–300ms。**

> 同上论文：预警时长集中在 800ms 左右，但玩家实际只在最后 200–300ms 才真正注意到。所以**预警必须"越接近命中越亮"**，把信息压到最后一段。

### 4.3 改造方案

**配色重新分工（四层，互不重叠）**

| 层 | 用途 | 颜色 | 依据 |
|---|---|---|---|
| 威胁 | 敌弹、BOSS 弹幕、预警圈 | **洋红 → 粉白核心**（#ff2e88 → #ffd6e8） | 弹幕游戏的通行危险色，和地面蓝灰互补 |
| 我方 | 玩家子弹、超武 | **青 / 青绿**（#30d5ff / #7dffd4） | 与威胁色在色相环上相距 120°+ |
| 战利品 | 经验球、宝箱 | **金**（#ffd24a）保持 | 已有黑描边，灰阶可读 |
| 环境 | 地面、墙壁、特效 | 蓝灰、低饱和 | 保持现在的白天基调 |

**关键改动：把玩家子弹从洋红搬走。** 现在 `bulB`（回旋镖/炸弹）用的是 `COS.mag`（洋红），必须改到青绿，把洋红整条让给危险。

**投掷手的预警三件套（按 800ms 设计）**

| 阶段 | 时长 | 表现 |
|---|---|---|
| 抬手蓄力 | 0–0.45s | 身体微缩、右手弹药球放大并变亮，脚下出现一圈洋红细环（0.45s 内从外向内收缩到最小） |
| 出手瞬间 | 0.1s | 枪口白闪 + 一圈洋红冲击环 + 低频"咚"（与玩家高频"咔"区分） |
| 弹道飞行 | 1.5s（17 单位 / 11 速） | 洋红弹体 + 粉白核心 + 3 段拖尾；命中前 0.15s 弹体放大 1.3 倍并高亮 |

**渲染层级**：敌人子弹永远画在最上层（3D 里用 `renderOrder` + `depthWrite:false`），不被粒子、爆炸、玩家遮住。

> 依据：Boghog 明确要求"敌人子弹必须绘制在其他所有对象之上"；gamineai 的 VFX 分层模型给了具体时间预算（预警 120–220ms 起、保持 250–550ms；命中闪光 40–90ms）。

## 五、打开网页要等几秒才有歌

### 5.1 实测（本机，冷缓存）

| 节点 | 时间 |
|---|---|
| three.js 下载完成 | 617 ms |
| `window.POW` 可用（游戏可交互） | 793 ms |
| 首次绘制 | 832 ms |

本机是快的（CDN 边缘节点近）。但这个数字是**串行的**：`<script src>` 在 `<head>` 里、没有 `defer`，所以 613 KB 的 Three.js 没下完，后面的 CSS 和 body 都不会解析——**首屏和可点击时间都被它绑住**。网络慢一倍，这些数字就翻倍。

### 5.2 真正的两个原因

**原因一：加载是同步阻塞的。**

```html
<script src="https://unpkg.com/three@0.150.1/build/three.min.js"></script>
<script>window.THREE||document.write('<script src="https://cdn.jsdelivr.net/...">')</script>
<style> ... </style>
```

样式表排在脚本后面 → 首帧要等 613 KB 下完。这期间**点击是无效的**（`unlockAudio` 还没绑定）。

**原因二：浏览器规定"必须用户手势才能出声"。**

`BGM.start()` 只在 `pointerdown / keydown` 里调用。不点，就永远没声音。

**所以"等几秒才有歌"= 加载那 1–3 秒里你点了但没生效 + 加载完再点一次才出声。** 不是音乐的锅。

### 5.3 方案（三档）

| 档 | 做法 | 效果 | 代价 |
|---|---|---|---|
| 轻 | 把 `<style>` 移到 `<script>` 之前 | 首屏立刻出画面，不再是白屏 | 0 |
| 中（推荐） | three.js 加 `defer` + 显式"点击开始"遮罩（一次点击 = 初始化音频 + 起播音乐 + 进标题） | 加载和点击解耦，玩家永远不会"点了没反应" | 小 |
| 重 | 把 613 KB 的 three.js 内联进 HTML | 彻底无网络依赖，断网也能玩 | 文件 200 KB → 800 KB |

我建议**轻 + 中**，先不内联：内联让文件变大 4 倍，而收益只对"网络极差"的场景明显。

⚠ **中档不是"加个属性"那么简单，有一个坑必须先处理。**

现在 CDN 备用源是靠 `document.write` 写的：

```js
<script>window.THREE||document.write('<script src="...jsdelivr..."><\/script>')</script>
```

一旦给 three.js 加 `defer`，这个兜底会**在文档关闭之后执行 `document.write`，把整页内容冲掉**。正确改法是一次小的加载器重写（约 25 行）：

1. 删掉 `document.write`，换成 `onerror` 回调动态插入备用源
2. three.js 与游戏主脚本都标 `defer`，靠顺序保证 `THREE` 先就绪
3. 主脚本开头加 `if(!window.THREE)` 的失败分支，显示"资源加载失败，点击重试"

这是这批改动里唯一有"改坏风险"的一处，所以放在第 2 批单独做、单独验证。

## 六、超武：现在确实只是"数值变大"

### 6.1 现状（代码事实）

| 超武 | 现在做的 | 有没有新机制 |
|---|---|---|
| 箭雨（弓） | 1→12 发扇形、全穿透、伤害 ×1.45 | 只有"更多箭" |
| 湮灭射线（激光） | 3→4 束、持续 1.35s、伤害 ×1.9 | 只有"更粗更久" |
| 血月斩（镰刀） | 4→6 刃、范围 ×1.6、命中吸血 | 有吸血，算半个 |
| 陨石雨（炸弹） | 4→6 颗、伤害 ×1.7、半径 +50% | 只有"更多" |
| 无限回旋（飞镖） | 4 枚、穿透 3、追踪 3.2s | 追踪算半个 |
| 荆棘领域（地刺） | 5 片、范围 ×1.5、时长 3.6s | 只有"更大更久" |

**你说得对，这些是"同一个动作放大"，不是新玩法。** 判据很简单：如果玩家不看数字，只看画面，能不能说出"我进化了"？现在说不出来。

### 6.2 设计原则：超武 = 常态小强化 + 周期性"必杀"

```
超武形态 = 基础形态强化（+15%，保证下限）
         + 每 5–8 秒一次的「必杀事件」（提供辨识度和爆发）
```

三条硬规则：
1. **必杀必须有独立视觉语言**（新的形状 / 新的颜色 / 新的声音），不能只是"原来那个变大"
2. **必杀必须有前摇**（0.3–0.5 秒），玩家能预期、能配合走位
3. **必杀不能替代操作**，只能是"多一个节奏点"，不能变成"站着自动清屏"

### 6.3 六个超武的具体机制（按你的建议细化）

**① 穿透激光 → 「过载贯穿」**

- 周期：6.5 秒
- 前摇：0.35 秒，炮口白闪、角色周围出现一条细的洋红瞄准线（指示将要打的方向）
- 释放：一条**宽度 ×4** 的光柱，持续 0.5 秒，沿直线贯穿全屏，对路径上每个敌人每 0.1 秒结算一次
- 单体等效：约 500 伤害（≈3 秒常态输出）
- 视觉：白热核心 + 洋红边缘 + 屏幕横向轻微拉伸；命中处连续爆白色火花
- 为什么有辨识度：**从"点"变成"面"**，玩家能明显看到一条线清空

**② 爆裂弓 → 「暴雨模式」**

- 周期：7 秒
- 前摇：0.3 秒，角色脚下出现青色的扇形指示
- 释放：进入 1.8 秒连射态，攻速 ×2.6、弹数 3、射程 −20%
- 单体等效：约 520 伤害
- 视觉：角色周围出现箭羽环，屏幕边缘出现速度线，音效变密集的"哒哒哒"
- 为什么有辨识度：**声音和节奏突然变快**，这是最容易感知的变化

**③ 抛掷炸弹 → 「空袭」**

- 周期：7 秒
- 前摇：0.45 秒，地面出现 12 个洋红细圈（落点预告，从外向内收缩）
- 释放：12 颗小炸弹落在半径 7 的圆内，每颗 0.8× 单发伤害；**命中 ≥8 次**追加一颗大炸弹（半径 ×1.8，伤害 5× 单发）
- 单体等效：约 310 伤害
- 视觉：先看到"靶子"，再看到"地毯式爆炸"，最后大炸弹的白热闪光
- 为什么有辨识度：**先预告后爆发**，有节拍

**④ 回旋镖 → 「超旋」**

- 周期：5.5 秒
- 前摇：0.3 秒，飞镖开始绕身盘旋并逐渐加速（视觉上先"上弦"）
- 释放：1.5 秒内半径 ×2.2、转速 ×1.8、数量 ×2、穿透无限
- 单体等效：约 300 伤害
- 视觉：一圈洋红残影 + 环形气流；期间玩家可以主动往怪堆里走（收益最大化）
- 为什么有辨识度：**范围瞬间翻倍**，并且鼓励玩家改变走位

**⑤ 环绕镰 → 「血月」**

- 周期：6 秒
- 前摇：0.4 秒，刀刃停转并开始发红光
- 释放：半径 ×2 + 把范围内敌人**拉向自己 0.4 秒（聚怪）**，然后一次 4× 伤害斩击并吸血
- 单体等效：约 400 伤害
- 视觉：血色满月环从脚下一层层推开，聚怪时敌人被拖拽的轨迹
- 为什么有辨识度：**聚怪是全新的交互**，玩家会主动等它

**⑥ 地刺 → 「荆棘爆发」**

- 周期：5 秒
- 前摇：0.35 秒，地面出现 16 个裂纹点
- 释放：环形 16 枚地刺同时弹出，每枚 0.9× 伤害 + 减速 30%（2 秒）
- 单体等效：约 320 伤害
- 视觉：地面先裂开，再整圈弹起，带土屑粒子
- 为什么有辨识度：**从"沿路撒"变成"以我为圆心爆一圈"**

### 6.4 平衡框架（这才是"威力平衡"的算法）

不要逐个拍数字，用同一个式子算：

```
超武总 DPS 增益 = 基础强化增益 + 必杀折算增益
必杀折算增益   = 单次必杀等效伤害 × 每秒触发概率
单次必杀等效伤害 = 常态 DPS × 目标秒数（2.5–3.5 秒）
```

目标：**6 个超武的 DPS 增益全部落在 +45% ~ +55%**，方差 ≤ 1.2 倍。

| 超武 | 常态强化 | 周期 | 单次等效 | 折算增益 | 合计 |
|---|---|---|---|---|---|
| 过载贯穿 | +15% | 6.5s | 3.0 秒 | +46% | **+61%** ⚠ |
| 暴雨模式 | +15% | 7.0s | 2.9 秒 | +41% | **+56%** |
| 空袭 | +15% | 7.0s | 2.2 秒 | +31% | **+46%** |
| 超旋 | +15% | 5.5s | 1.7 秒 | +31% | **+46%** |
| 血月 | +15% | 6.0s | 2.4 秒 | +40% | **+55%** |
| 荆棘爆发 | +15% | 5.0s | 1.9 秒 | +38% | **+53%** |

表里第一行就要下调（贯穿 3.0 秒 → 2.5 秒，或周期 6.5 → 7.5 秒）。**这个表只是起点，最终数值必须用已有的 4 智能体测试跑 20 个样本收敛**，因为"等效伤害"里有一堆假设（命中率、敌人密度）。

而且要防一个副作用：超武爆发会让 BOSS 的 TTK 变短。BOSS 血量是按"进化前 DPS"派生的，所以超武会让实际时长掉 20–30%。**改超武的那一次，必须同时把 BOSS 的目标秒数上调补偿**，否则会打回"BOSS 太脆"。

## 八、我建议的推进顺序

分四批，每批独立提交、独立验证：

| 批次 | 内容 | 为什么这个顺序 |
|---|---|---|
| 第 1 批 | 震屏 trauma 化 + 敌弹配色/预警/音效分离 | **纯体验修复，不改数值结构**，风险最低，且立刻能感知 |

| 第 3 批 | 流派属性 + 卡池权重 + 超武前置改流派 | **改的是构筑系统**，会牵动 `estimateDPS` 与 BOSS 派生 |
| 第 4 批 | 6 个超武的必杀机制 + BOSS 时长上调 | 依赖第 3 批的 DPS 口径，放最后 |

每批的验收：

- 第 3 批：4 智能体测试，看四种策略的配装是否真的分化（现在 balanced/rush/passive 常常撞成同一套）
- 第 4 批：BOSS 样本均值 32 / 45 秒，偏差 < 1.15×；六个超武 DPS 增益方差 < 1.2×

## 九、需要你定的三件事

1. **流派属性要不要"锁死"？** 我倾向"不锁"（可以混点，但混点效率低），而不是"选了近战就不能拿弓"。
2. **BOSS 30–45 秒是"墙钟"还是"打血时间"？** 我按墙钟理解（含转阶段），所以血量只涨 1.7 倍。
3. **超武必杀要不要手动触发？** 现在是自动周期触发（更像"被动爆发"）。如果做成"满能量后按键释放"，操作感更强，但会改变游戏的操作模型（目前是纯走位）。
