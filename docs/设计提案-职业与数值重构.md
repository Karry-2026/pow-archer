# 设计提案：职业、数值、构筑与工作流重构

日期 2026-10-28 · 状态：**提案，未实施** · 对应版本 v0.17.1

---

## 0. 一句话

现在的六个职业、六把武器、三条流派，是在「一个能跑的原型」上叠出来的，不是设计出来的。要让它像个正式作品，需要做三件事：**把武器从「DPS 竞争者」改成「功能位」**、**把数值从手调改成可核算的账本**、**把随机发牌改成「过滤后的三选一 + 金币商店」**。三件事共用同一套底层：逻辑脱离渲染，能跑模拟。

下面每一条都先给证据，再给方案，最后给代价。

---

## 1. 先看证据：我们现在的数字到底是什么

### 1.1 表上的平衡是假的

按公式算，六把武器 Lv5 清怪 DPS 落在 133–169，极差 1.27 倍，看起来「已经调平」。但同一套配装跑出来的**实测总输出**是这样：

| 武器 | 表上 DPS | 实测 | 实测 / 表单体 |
|---|---|---|---|
| 地刺 | 151.5 | 1011 | **30.6×** |
| 爆裂弓 | 157.9 | 384 | 1.24× |
| 回旋镖 | 133.0 | 322 | 1.31× |
| 穿透激光 | 144.8 | 277 | 1.04× |
| 抛掷炸弹 | 150.6 | 271 | 1.35× |
| 环绕镰 | 169.0 | 101 | 1.38×（对表单体）；对表清怪是 **0.37×** |

同一套「平衡」的表，实测拉开 10 倍。**原因不是哪把武器数值错了，是我们从来没定义过测量场景**：地刺在「站着不动、怪自己走进雷区」的测试里是神，在「边跑边铺、永远背对怪群」的实战里是废。两个数都是真的，只是回答的不是同一个问题。

### 1.2 必杀的收益有两个是负的

设计口径是「单次必杀 ≈ 1.7–3.0 秒常态输出」。实测净值（伤害折秒 − 施法耗时）：

| 必杀 | 等效 | 净增益 |
|---|---|---|
| 过载贯穿（激光） | 1.11 秒 | **+0.01 秒** |
| 超旋（飞镖） | 1.63 秒 | **−0.21 秒** |
| 血月（镰刀） | 2.43 秒 | +0.78 秒 |
| 暴雨（箭雨） | 3.89 秒 | +1.44 秒 |
| 空袭（炸弹） | 3.62 秒 | +2.02 秒 |
| 荆棘爆发（地刺） | 1.69 秒 | +0.39 秒 |

两个「按了不如不按」的必杀，玩家不会说「数值不对」，会说「这游戏没做完」。

### 1.3 BOSS 时长偏离目标 60–70%

设计写的是 32 / 45 秒。实测 55.3 / 72.0 秒。根因是血量标定只在开战 3.5 秒内采样一次 DPS，而那 3.5 秒是玩家全场唯一站着不动输出的时间。

### 1.4 一局的决策量小于内容量

一局 10 波约 22–25 次升级。六把武器各 5 级 = 30 次，加三条流派精通 15 级、三个通用被动 15 级、六次进化。**内容量是一局能拿到的两到三倍**，所以「抽到什么就玩什么」必然发生，玩家也就必然觉得「我玩射击，它给我炸弹」。

## 2. 问题一：职业与武器 —— 从「六个 DPS」改成「六个功能位」

### 2.1 别人怎么做的

《吸血鬼幸存者》的六把武器不是六个 DPS 档位，是六种功能：

| 武器 | 实际定位 |
|---|---|
| 大蒜 Garlic | 光环，伤害很低，作用是**推开近身怪、给走位留空间** |
| 圣经 King Bible | 环绕护盾，贴着转，作用是**别人不敢近身** |
| 鞭子 Whip | 横向穿透，作用是**在正面开一条路** |
| 魔法杖 | 自动锁最近目标，用处是**稳定输出** |
| 闪电环 | 随机点名，作用是**被动清场** |

近战武器在幸存者 like 里从来不是「DPS 更高所以值得贴脸」，它们卖的是**空间、控场、护盾、清路**。玩家不会拿大蒜去和魔法杖比 DPS。

近战和远程的 DPS 差多少才算平？没有人能算出来 —— Warframe 论坛上有一条推导值得看：设近战 DPS 是远程的 1.5 倍，敌人血量低时两者等价，血量涨到 3 倍时近战快 50%，涨到 30 倍时近战就是唯一解。**不存在一个固定倍数能让两者永远平衡**，只能让它们承担不同职责（[Warframe 论坛](https://forums.warframe.com/topic/1249610-ranged-weapons-and-melee-weapons-should-rely-on-each-other-for-maximum-effectiveness)）。同一篇里给了三条出路：不同角色、限制使用次数、互相依赖。

### 2.2 我们的问题

我们让六把武器竞争同一个指标（清怪 DPS），然后在表上把它们调平。但玩家的手感和表不一致，因为：

**有效输出 = 名义 DPS × 命中率 × 有效时间占比**

远程武器两项都接近 1；近战和陷阱两项都低。名义相同，体感差 3–4 倍。这不是数值 bug，是**职责设计缺失**。

### 2.3 方案

给每把武器一个主功能，平衡目标从「DPS 相等」改成「在它擅长的场景里是前二选择」。

| 武器 | 主功能 | 付费方式（它牺牲什么） |
|---|---|---|
| 爆裂弓 | 单体点名 | 对群弱，扇形散开只有一半命中 |
| 穿透激光 | 直线清线 | 要求站位成一条线，被包围时差 |
| 抛掷炸弹 | 范围清场 | 冷却长，落点延迟 |
| 环绕镰 | 近身护盾 | 必须贴脸，DPS 中等 |
| 地刺 | 减速与封锁 | 伤害低，要求怪走进来 |
| 回旋镖 | 往返穿透 | 轨迹可预测，贴脸时打不到 |

配套三条硬规则：

1. **近战/陷阱不再参与 DPS 排名**。它们的设计指标是「每秒减少的威胁量」：击退距离、减速比例、挡下的弹幕数。
2. **每把武器必须有一个「远程做不到」的场景**。地刺的答案是「把追兵钉在原地」，环绕镰是「挡掉贴脸弹幕」。做不到就别留在池子里。
3. **数值上调只调功能强度，不调 DPS**。地刺要加强，加的是减速 40% → 55%、持续时间 3.2 → 4.0 秒，不是伤害数字。

### 2.4 代价

玩家会第一次面对「这把武器不负责杀怪」的概念，需要教学。地刺类武器如果控场做得不够明显，仍然会被当成废牌 —— 这需要一次真人试玩确认。

## 3. 问题二：数值 —— 从手调改成三层账本

### 3.1 现在为什么「想当然」

- 波次血量倍率 1.75 是拍的，没有人验证过它对应什么体验
- `EXPECTED_DPS` 十个数是手抄的，和实际配装脱节
- 武器参数（伤害 / 冷却 / 弹数）各自手调，没有共同的计价单位
- 表格、代码、文档三处副本，v0.16 一次对账查出 6 处不一致

### 3.2 业内做法

**锚点法**：先定一个基准单位（1 点伤害 = 多少秒 = 多少金币），所有数值相对锚点表达，不做绝对平衡（[Ludo Atlas](https://github.com/HuanMoovo/ludo-atlas/blob/HEAD/docs/fundamentals/game-design/README.md)）。

**分段曲线**：前期线性建立爽感，中期缓指数，后期陡指数；单一曲线撑不住完整生命周期（同上，以及[数值设计课程](http://mp.weixin.qq.com/s?__biz=MzY5MDI4NTczNw==&mid=2247483774&idx=1&sn=ded38fa92d2b762153fa129dce5f3e51)）。

**功率预算（power budget）**：给每件装备固定「功率点数」，每个属性有单价，做完就没了。这是把「升级强度」变成可核算的账本（[Chroma Golem 的预算表](http://chromagolem.com/documentation/build/items)：1 点伤害 = 1 点，1% 暴击 = 5 点，1% 移速 = 10 点，主属性占预算 60%）。

**先表后码**：所有可调数值进表，代码只读表（Ludo Atlas 4.1）。

### 3.3 方案：三层账本

**第一层 · 锚点**

```
1 单位 = 玩家 Lv1、单把起手武器、无被动时的清怪 DPS
所有武器、被动、敌人血量都以这个单位标价
```

**第二层 · 成长曲线（分段）**

| 波次 | 曲线 | 目的 | 参数 |
|---|---|---|---|
| 1–3 | 线性 | 教学，玩家能看清每只怪 | 敌人血量 ×1.0 → ×2.0 |
| 4–7 | 指数 | 构筑成型，压力回升 | ×2.0 → ×12（每波 ×1.8） |
| 8–9 | 陡指数 | 检验构筑是否成立 | ×12 → ×27（每波 ×1.5） |
| 10 | 阶梯 | BOSS 收尾 | 单独按 DPS 派生，不用波次公式 |

现在的 1.75 每波单一指数，到第 10 波是 154 倍，全程一个斜率 —— 前松后紧，中间没有节奏。分段之后，第 4–7 波才是真正的「构筑考验期」。

**第三层 · 功率预算**

每次升级发 100 点预算，各属性按单价花：

| 属性 | 单价（点） | 说明 |
|---|---|---|
| +1% 武器伤害 | 1.0 | 基准 |
| +1% 攻速 | 1.6 | 攻速乘伤害，边际更高 |
| +1 生命上限 | 0.3 | |
| +1% 移速 | 2.0 | 走位是核心资源，最贵 |
| +1% 拾取范围 | 0.4 | |
| +1% 暴击 | 3.0 | 后期乘区 |
| +1 次弹数 | 12 | 弹数是乘性的，最贵 |

好处：加血和加炸弹不再互相「浪费」，它们花的是同一笔预算；策划改一个单价，全表自动重算。

**第四层 · 敌人血量反推，不再手写**

```
敌人血量(波 w) = 模拟得到的 P50 玩家 DPS(w) × 目标 TTK(w)
```

跑 1000 局蒙特卡洛（固定策略 bot），取中位数 DPS 曲线，直接反推血量。这样 `EXPECTED_DPS` 这张手抄表就废掉了 —— 它本来就是「人猜的典型配装」。

### 3.4 代价

模拟器要先有。这就是第 6 节的工作流。

## 4. 问题三：流派过多 —— 从 3 条线 6 把武器收到 2 条线 3 个槽

### 4.1 现状

3 条流派线（射击 / 贴身 / 投掷）× 6 把武器 × 5 级 + 3 个通用被动 + 6 次进化 + 6 个必杀 + 6 个职业。

一局 22–25 次升级，最多升满 4 把武器。

### 4.2 方案：把「内容量」对齐到「决策量」

| 项 | 现在 | 提案 | 理由 |
|---|---|---|---|
| 流派线 | 3 | **2**（远程 / 近身） | 三条线意味着一局至少三个方向都想要资源，玩家会散 |
| 武器槽 | 4 | **3** | VS 用 6 槽是因为一局 30 分钟、能升 40 级；我们只有 22 级 |
| 被动槽 | 6 | **2** | 被动的作用是「补强」，不是第二个构筑系统 |
| 武器等级 | 5 | 5（保留） | |
| 进化条件 | 满级 + 对应精通 3 级 | **满级 + 对应被动 2 级** | 精通线取消后，条件改成「带对被动」 |
| 职业 | 6 | **4**（每线 2 个） | 对应四条功能轴：散射 / 贯穿 / 近身 / 封锁 |

算一下：3 武器 × 5 级 = 15 次，2 被动 × 3 级 = 6 次，进化 1 次，剩 0–3 次给金币或重掷。**刚好用满，不多不少。**

### 4.3 为什么砍到 2 条线不是砍内容

六把武器可以全留，只是每局只能拿 3 把。玩家下一局换三把，就是另一套玩法。**内容量留在池子里，不留在单局里** —— 这是幸存者 like 的基本结构（VS 26 把武器，一局只带 6 把）。

## 5. 问题四：随机发 buff —— 不是随机的错，是池子没过滤

### 5.1 诊断

现在的问题不是「随机会给不相关的东西」，而是：

1. **池子不看你已经投了什么**：射击流照样抽到炸弹
2. **没有「不选」的选项**：三张都不想要只能硬吃
3. **新武器和武器升级混在一起**：抽到新武器 = 占用槽位 = 隐性惩罚

### 5.2 业内两条路

**路线 A：三选一 + 池子分层（VS / Hades）**

VS 升级抽卡，但池子随你已有的东西变化；Hades 的祝福按神分层，不同神对应不同方向。关键是**「随机发生在选项上，不在结果上」**（input randomness，见 [Theseus 论文](http://www.theseus.fi/bitstream/10024/886802/2/Hannula_Rama.pdf)）。论文同时提醒：选项之间必须「大致同样可行」，否则选择就变成假选择。

**路线 B：金币 + 波间商店（Brotato）**

Brotato 每波结束进商店，4 件商品，可 reroll、可锁定。它有精确的公式（[Brotato Wiki](https://brotato.wiki.spellsandguns.com/index.php?title=Shop)）：

```
通胀价 = 基础价 + (基础价 × 10% + 1) × 商店序号
商店构成：35% 武器 / 65% 道具
武器来源：20% 与你已有同款 / 15% 同类别 / 65% 全池
稀有度按波次解锁（Tier2 从第 1 波、Tier3 从第 3 波、Tier4 从第 7 波）
```

「同款 20% / 同类 15%」就是**按已有构筑加权**的落地写法，比我凭感觉给的权重靠谱。

**路线 C：纯金币，取消三选一**

你提的方案。优点是彻底消除「随机给我不需要的东西」，缺点是每局趋同 —— 所有人都买同样的三件套，roguelite 的重玩价值消失。

### 5.3 推荐：A + B 混合，不做 C

```
击杀 / 波次结算 → 金币
       ├─ 升级（22 级）→ 三选一，池子已过滤
       └─ 波间（10 次）→ 商店 4 格，可 reroll / 锁定
```

**三选一的池子规则**（解决「射击流给炸弹」）：

| 规则 | 内容 |
|---|---|
| 主池 | 已持有武器的升级 + 已持有武器的进化 |
| 副池 | 与已持有武器同流派的被动 |
| 通用池 | 生命 / 移速 / 拾取（不与流派冲突） |
| 新武器 | **只在武器槽未满时出现**，且卡片明确标「新武器 · 占 1 槽」 |
| 保底 | 三张里至少一张是「当前最强武器的升级」 |
| 惊喜下限 | 至少 10% 概率给一张池外卡（保留发现感，参考 Ludo Atlas 的「至少三成随机」下调版） |

**金币商店的参数**（照 Brotato 的结构改）：

| 项 | 值 | 说明 |
|---|---|---|
| 每波金币 | 8 + 波次 × 4 + 击杀数 × 0.3 | 第 5 波约 40–60 |
| 商品数 | 4 | |
| 价格 | 30 / 45 / 60（按品级） | |
| Reroll | 首次 10，每次 +8 | 第 5 波后可负担 2–3 次 |
| 通胀 | 每波 +10% 基础价 + 1 | 防囤积 |

这样「想加血」就花钱买，不占升级位；「想玩炸弹」就在商店里买，而不是被随机塞进手里。

### 5.4 代价

多一个界面（商店）+ 一套经济曲线，工期约 2 天。收益是：玩家第一次能「按自己的意思」变强，这直接对应你说的「更正规」。

## 6. 问题五：工作流 —— 现在的流程在哪一步坏了

### 6.1 复盘这个项目的实际流程

| 环节 | 现状 | 后果 |
|---|---|---|
| 设计 | 想到就加，先写代码再想为什么 | 六职业、六武器、三条线，谁也不认识谁 |
| 数值 | 在代码里手调，表格是抄出来的副本 | v0.16 对账查出 6 处不一致 |
| 代码 | 单文件 6,263 行，逻辑和渲染焊死 | 改一处要全局搜，模拟跑不起来 |
| 验证 | 无头浏览器脚本，端口硬编码，人工记得跑 | 用例从没串起来跑过；`touch` 三条断言红了没人发现；并行跑四个浏览器会把机器压垮 |
| 文档 | 手写同步，版本号四处 | 版本号在四个文件里各不相同 |

### 6.2 提案：四个改动

**① 分层：逻辑必须能在 Node 里跑**

```
sim/     纯逻辑：数值、波次、武器、掉落、结算（不 import three）
render/  Three.js：只读状态、写画面
ui/      DOM
data/    JSON：所有可调参数
build.mjs 把 sim + render + ui + data 内联成单 HTML
```

单文件交付不变，开发和测试不再需要在浏览器里。

**② 数值单一来源**

所有参数进 `data/*.json`，表格、手册、曲线图都由脚本生成。人只写「为什么」，不写「是多少」。v0.16 那次对账脚本要升级成构建时的硬门禁。

**③ 模拟即平衡**

```
node sim/balance.mjs --runs 1000 → 输出：
  每波 P50 / P90 DPS 曲线
  每把武器的有效输出（区分单目标 / 群怪 / 被围三种场景）
  通关率、平均存活波次、死于第几波
```

**「有效输出」必须在三种标准场景里测**，这是第 1 节那个 10 倍误差的解药。场景固定，数字才有意义。

**④ 一次命令跑完所有验证**

```
npm test        → 单元 + 布局 + 交互（固定端口，串行，自带服务）
npm run sim     → 1000 局平衡报告
npm run audit   → 表 / 代码 / 文档三方对账
npm run build   → 生成单 HTML + 手册
```

### 6.3 顺序（重要）

不要一次全做。按这个顺序，每步都能独立回滚：

| 步骤 | 内容 | 工期 | 风险 |
|---|---|---|---|
| 1 | 抽 `sim/`，把数值与结算搬出去，跑通「不开浏览器也能打完一局」 | 1.5 天 | 低（纯搬移，行为不变） |
| 2 | 写三种标准场景的模拟，出一份「六武器真实输出」报告 | 0.5 天 | 低 |
| 3 | 用报告重做数值账本（锚点 + 分段曲线 + 功率预算） | 1 天 | 中（数值会变） |
| 4 | 按功能位改武器（第 2 节）+ 收敛流派到 2 线 3 槽 | 1.5 天 | 中（玩法会变） |
| 5 | 三选一池子过滤 + 金币商店 | 2 天 | 高（新界面） |

**参赛截止 11-01，只剩 4 天。** 我的判断：**第 1、2 步必须做**（后面所有事的地基，且不改变现有体验），第 3 步做一半（重算曲线，不动武器手感），第 4、5 步放到赛后。赛前动玩法和界面，等于拿完成度换「更正规」，评审看不到你的架构，只看到打不开的链接。
