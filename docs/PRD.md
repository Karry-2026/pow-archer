# POW! ARCHER 需求文档

版本 v0.2 · 2026-10-23

---

## 1. 项目定位

一个跑在浏览器里的 3D 俯视角割草游戏，美漫风格，用来参加 WorkBuddy「1024 造物挑战」程序员节应用创作大赛。

长期目标是做成一个可以独立运营的项目，短期目标只有两个：在 11 月 1 日前投出去，拿到一个体面的名次。

评分结构决定了取舍：

| 维度 | 分值 | 对策 |
|---|---|---|
| 创意与场景价值 | 35 | 割草 + 美漫视觉 + 超武进化，避开工具类红海 |
| 作品完成度 | 40 | 权重最高。核心循环必须闭环，评审打开不能报错 |
| 使用体验 | 25 | 3 秒看懂，全程只需要走位，零学习成本 |
| 社媒分享加分 | 30 | 后期用录屏素材做短视频，这部分是可控分 |

## 2. 需求 1：界面与描述要更直接

### 现状问题

升级卡片上写的是「武器强化 Lv.3 → Lv.4」加一段形态描述。快节奏游戏里玩家只有两三秒做决定，这种写法要读两遍才能判断该不该选。

### 改法

卡片信息重排，四段结构：

| 位置 | 内容 | 目的 |
|---|---|---|
| 顶部色块 | 武器缩写（BOW / LAS / SCY） | 一眼认出是哪把武器，不用读名字 |
| 类型标签 | 武器强化 / 被动 / 超武进化 / 极限突破 | 先知道这是哪一类决策 |
| 名称 | 爆裂弓 | |
| **核心数字**（加粗大字，上下加黑线） | `Lv.3 → Lv.4` / `+16% 伤害` / `12 发扇形` | 一个数字决定选择 |
| 一行说明 | 三向散射 | 补充形态变化 |

武器和被动各给一个固定颜色，长期玩下来可以形成颜色记忆。

### 验收

不看说明文字，只扫一眼卡片，能在 2 秒内说出这张卡给的是什么。

## 3. 需求 2：画风保留，优化丝滑感和特效

画风和打击感用户明确认可，不动。只做加法。

| 改动 | 效果 |
|---|---|
| 相机朝移动方向前瞻 1.9 单位 | 往哪走视野就往哪偏，走位更跟手，不再有「撞到屏幕边缘」的迟滞感 |
| 卡片错峰入场（每张延迟 55ms，带旋转和缩放回弹） | 三张卡依次弹出，比同时出现更有节奏 |
| 暴击时在命中点喷黄色碎块 + 伤害数字 | 暴击有独立反馈，不再是数字变大而已 |
| 精英怪脚下旋转的黄色光环 | 一眼分辨精英和杂兵，知道该先打谁 |
| 受击脉冲从 1.3 倍改到 1.34 倍，衰减加快 | 打击更脆，回弹更快 |
| 敌人移动加轻微上下浮动，尖刺兽加自转 | 减少「一堆静止多面体在平移」的呆板感 |

### 刻意没做的

**不加屏幕后处理（泛光、色差、景深）**。这类效果要接 EffectComposer，多加载三个脚本模块，中低端核显上直接掉帧。现在靠卡通着色加描边已经够风格化，加后处理是拿性能换观感，不划算。

## 4. 需求 3：难度梯度

### 问题诊断（实测数据）

| 数值 | 第 1 波 | 第 10 波 | 变化 |
|---|---|---|---|
| 敌人血量倍率 | 1.00 | 4.06 | 4.1x |
| 敌人伤害 | 固定 7-16 | 固定 7-16 | 1.0x |
| 玩家可达 DPS | 15 | 500+ | 30x 以上 |

结论：敌人伤害完全不成长，玩家 DPS 涨 30 倍。所以「怪很多但打不死你」。

另外发现一个数值 bug：环绕镰的冷却写成 0.05 秒，等于每秒触发 34 次 AOE，单目标 DPS 513，比单体激光还高两倍，导致其他武器失去存在意义。

### 设计依据

全部来自公开资料，不是拍脑袋。

| 来源 | 借用内容 |
|---|---|
| TTK 平衡框架（PvE 杂兵 2-5 秒 / 精英 15-30 秒 / BOSS 2-5 分钟） | 用来定敌人血量区间 |
| 锯齿（sawtooth）难度模型 | 章节起点低于玩家强度、段中追平、BOSS 超 10-20%、下段回落 |
| 「线性递增 + 阶梯跳跃」配平法 | 每波小涨 + 每若干波额外跳一档，避免突兀 |
| 《吸血鬼幸存者》的 Limit Break 机制 | 满级后转为无限叠加，解决后期空池 |
| 曲线错配警告（敌人指数 vs 玩家线性 → 落差无限扩大） | 反过来验证我们当前是玩家成长远超敌人 |

### 方案

敌人血量与伤害放弃线性公式，改成查表，表按锯齿设计：

| 波次 | 血量 | 伤害 | 刷怪率 | 设计意图 |
|---|---|---|---|---|
| 1 | 1.00 | 1.00 | 1.00 | 呼吸区，学操作 |
| 2 | 1.12 | 1.02 | 1.10 | |
| 3 | 1.38 | 1.16 | 1.24 | 台阶：尖刺兽入场 |
| 4 | 1.52 | 1.20 | 1.34 | |
| 5 | 1.92 | 1.34 | 1.28 | 尖峰：BOSS，同时降刷怪率让玩家专心打 |
| 6 | 1.66 | 1.38 | 1.48 | 回落 13%，台阶：投掷手入场 |
| 7 | 1.86 | 1.44 | 1.58 | |
| 8 | 2.32 | 1.58 | 1.72 | 台阶：肥球成群 |
| 9 | 2.68 | 1.72 | 1.84 | |
| 10 | 3.35 | 1.92 | 1.90 | 尖峰：最终 BOSS |

波内再线性递增：血量 +6%、伤害 +5%。避免一波 30 秒内强度完全一样。

配套三项：

1. **修环绕镰**：冷却 0.05 → 0.50 秒，单次伤害 42% → 100%。DPS 从 513 降到约 180。
2. **敌人伤害接曲线**：第 10 波 1.92 倍，玩家 240 血被碰 5-6 次要死。
3. **加精英怪**：第 3 波起出现，概率 3.5% 起、第 8 波后 13%。血量 5.5 倍、伤害 1.55 倍、经验 6 倍、必掉宝箱。

### 难度档位

用户选定「中等：要懂 build 才能过」，含义是新手第一次大概率死在第五波，理解武器搭配后能通。

### 待验证

曲线是按方法论推的，没经过真人试玩。第 3 波到第 5 波的爬升幅度（1.16 → 1.34 伤害）可能需要回调。

## 5. 需求 4：菜单重做

用户指明是升级三选一和背包两块。

### 升级三选一的死局

原逻辑：武器槽 4/4 满、被动全满、武器全 5 级后，可选项池为空，兜底逻辑塞三个治疗。

这是设计死局，不是显示问题。

新逻辑分五层，保证池子永不为空：

1. 超武进化（最高优先，会直接弹出）
2. 武器升级
3. 新武器（槽位未满时）
4. 被动
5. **极限突破**：满级武器可无限叠层，每层 +8% 伤害

治疗只在两种情况下出现：血量低于 45% 时替掉第三张卡；或者其它选项真的不足三张。

### 超武进化

| 武器 | 需要被动 3 级 | 进化名 | 核心变化 |
|---|---|---|---|
| 爆裂弓 | 攻速 | 箭雨 | 12 发扇形，全穿透 |
| 穿透激光 | 攻击 | 湮灭射线 | 4 束，持续 1.35 秒 |
| 环绕镰 | 移速 | 血月斩 | 6 刃，范围 +60%，命中回血 |
| 抛掷炸弹 | 暴击 | 陨石雨 | 6 颗，爆炸半径 +50% |
| 回旋镖 | 磁力 | 无限回旋 | 4 枚，穿透 + 追踪 |
| 地刺 | 生命 | 荆棘领域 | 5 片，毒池扩大 50% |

进化卡在视觉上有独立样式：紫色描边 + 外发光。

### 重掷

每局 3 次，三张卡不满意可以重摇。这是给「运气差」的保险，也是决策的一部分。

### 背包改动

| 改动 | 原因 |
|---|---|
| 顶部加总览条：预估 DPS、武器槽数、被动数、超武数 | 打开背包第一眼知道当前战力 |
| 武器卡加 5 格等级进度条 | 一眼看出离满级还差几级 |
| 武器卡加进化进度行：`进化 · 攻速 2/3`，条件满足时变绿显示「下次升级可进化」 | 告诉玩家下一个目标是什么，不用自己记 |
| 未满的武器槽显示为「空槽 · 开宝箱补满」 | 明确缺口和获取途径 |
| 弃用按钮文案从「×」改为「换掉」语义 | 明确这是替换，不是销毁 |
| 被动卡也加等级进度条 | 统一视觉语言 |

### 验收

全部内容满级后，连续升 10 级，不出现三张都是治疗的卡。

## 6. 需求 5：Godot 迁移调研

**这一项只做调研，不动代码。当前阶段的核心工作是参赛。**

### 结论

现在不迁。但应该现在开始按可移植的方式组织代码，把将来的迁移成本从「重写游戏」降到「重写渲染层」。

### 数据对比

| 维度 | Godot 4 Web 导出 | 当前 Three.js 方案 |
|---|---|---|
| 空项目包体 | Brotli 约 5 MB / gzip 约 9 MB | 核心 150 KB，整页 100 KB |
| 部署要求 | 需 COOP/COEP 跨域隔离头；不设则只能导单线程版，性能打折 | 无特殊要求，静态托管直接跑 |
| 渲染器 | Web 导出只支持 Compatibility，不支持 Forward+ | 全量 WebGL2 |
| 移动端 Safari | 有上游 bug，官方承认不稳 | 正常 |
| C# 支持 | Web 导出不支持 C#，只能用 GDScript | 不适用 |
| 上架 Steam | 原生支持 | 需套 Electron，无先例 |
| 迭代速度 | 改完要重新导出 wasm + pck | 改完刷新即生效 |

### 判断

1. **对这次参赛，Godot 是负分**。评审点开链接要先下 9 MB，还得托管方给对响应头。作品墙里没人会等。
2. **如果目标变成 Steam，Godot 是唯一正确选择**。Three.js 套 Electron 上 Steam 这条路不建议走。
3. **迁移的难点不在引擎，在架构**。当前渲染和逻辑焊死在同一个文件里，直接迁等于重做。

### 三条路线

| 路线 | 适用 | 成本 |
|---|---|---|
| 保持 Three.js，做纯网页 | 目标是网页传播、参赛、轻量体验 | 最低 |
| 迁 Godot，上 Steam | 目标是卖钱、长期运营 | 高（估算 2-3 周，单人） |
| 换 PlayCanvas | 只是嫌 Three.js 太底层，想要现成的实体组件系统 | 中（浏览器原生，1-2 MB） |

### 迁移前置条件

不管走哪条，现在就该做一件事：**把游戏逻辑和渲染分离**。

具体做法：把数值、波次、武器、升级、掉落、碰撞判定这些抽成一个纯 JS 模块，不引用任何 Three.js 的东西，可以脱离浏览器在 Node 里跑。渲染层只读状态、写画面。

这样做有三个好处：

1. 迁移 Godot 时逻辑可以直接翻译成 GDScript，不用重新设计
2. 数值平衡可以脱离游戏跑批量模拟，不用手动玩一局看结果
3. 改数值的时候不用动渲染代码，风险低

### 成本估算（估算，非实测）

当前 2159 行脚本，大致可以切成：

| 层 | 行数（估） | 迁移工作量 |
|---|---|---|
| 逻辑（数值、武器、波次、升级、掉落） | 约 1400 | 翻译成 GDScript，结构可复用 |
| 渲染（场景、材质、实例池、特效） | 约 500 | 在 Godot 里重建，shader 要重写 |
| UI | 约 250 | 用 Godot Control 重做 |

### 建议节奏

1. 先完成参赛版本，不动架构
2. 参赛结束后，做逻辑抽离（约 1-2 天），顺便获得数值模拟能力
3. 视参赛结果和后续规划，再决定要不要真的迁

## 8. 风险

| 风险 | 应对 |
|---|---|
| 真实显卡掉帧 | 所有实体走实例池，像素比上限 1.6，无后处理。若仍掉帧，降同屏敌人上限 |
| CDN 不可用 | 双源容灾，主源失败自动切 jsdelivr |
| 数值手感不对 | 曲线有依据但未试玩，留出 10-24 到 10-25 两天回调 |
| 撞车已有作品 | 割草 + 美漫视觉在已参赛作品里没有同类，风险低 |
