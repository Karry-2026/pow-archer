# 版本管理

一句话：**版本号、git 提交、在线链接三者必须能对上**。线上出问题，能立刻知道跑的是哪一版，并且能一键退回任何一个可玩状态。

本文是版本信息的唯一权威。`README.md` 只写当前一版的状态，`docs/DEVLOG.md` 写每一笔改动的原因，编号和归属以本文为准。

## 二、版本号规则

`v0.<MINOR>[.<PATCH>]`

| 位 | 什么时候加 | 例子 |
|---|---|---|
| MINOR | 玩家能感知的变化：玩法、内容、界面结构、数值口径 | v0.10 三流派、v0.14 开始界面重做 |
| PATCH | 只改文档、注释、版本标记，不改一行运行逻辑 | v0.14.1 本次文档回填 |

历史节奏：一局能玩 = 一个 MINOR，一批真机反馈修完 = 一个 MINOR。没有第三位，因为每次改动都同时碰了代码和文档，硬拆 PATCH 只是在制造噪音。

## 四、v0.8 之后每一版改了什么

v0.1–v0.7 的过程在 `docs/DEVLOG.md` 前 2,300 行和手册「开发记录」里有完整记录。这里补 v0.8 之后，也是手册长期缺的那一段。

### v0.8 · 配色重构 + BOSS 血量改实时派生

- 配色不再按色相调，按**明度**调：地面明度 95 → 82，前景靠描边壳拉轮廓。判断「看不清」的正确顺序是先转灰阶，目标消失 = 明度问题，目标还在但分不清 = 色相问题。
- 经验球第一次改金色（L84）在灰阶下仍消失，最后靠黑色描边壳（BackSide + 放大 1.34）解决 —— 黑（L10）和任何亮背景的差都在 65 以上。
- BOSS 血量从查表改成「开战 3.5 秒后实测单目标 DPS × 目标秒数」，同时删掉 `Math.max(2600, …)` 下限。
- 结算加「回到主菜单」。没有这个出口，放弃本局的玩家出不去。

### v0.9 · 起播没声音

1.07 秒才可听，第 1 秒音量只有峰值 1.4%。三个原因全是自己加的：1.4 秒指数淡入、首音预排 100ms、最薄小节放在最前。改成 62% 起、0.22 秒补满，预排压到 60ms，第一拍先给镲。低音包络从收到 `0.0008` 改成收到 26% 就接下一拍。

可复用判断：**没有前态可过渡的时刻不要淡入**。淡入只在有旧声音要让位时才有意义。

### v0.10 · 构筑系统

这一版把「乱加点」变成「选一条线」：

| 改动 | 之前 | 现在 |
|---|---|---|
| 被动 | 6 个全局乘区 | 3 张流派精通 + 3 张通用 |
| 套装 | 无 | 同线 2 把武器 = 伤害 ×1.30 |
| 卡池 | 均匀随机 | 加权把玩家往已有流派推 |
| 超武前置 | 武器满级 | 武器满级 + 本流派精通 3 级 |
| 震屏 | `Math.max` 顶回同一强度 | trauma 累加 + 平方映射 + 封顶 |
| 远程怪 | 冷却一到直接出弹 | 0.45 秒抬手预警，敌弹改洋红 + 白核 + 拖尾 |
| BOSS 时长 | 无明确目标 | 32 / 45 秒，62% 转阶段、30% 狂暴 |

### v0.11 · 超武演出

全屏色染 + 超武名大字 + 推镜。天降落箭重做（不再用屏幕空间算落点），飞镖改成去程 + 回程双弧。这一版同时把三张数值表和手册全部对齐代码 —— 之前文档落后了三个版本。

### v0.12 · 第一批真机反馈

| 反馈 | 根因 |
|---|---|
| 手机顶部三层文字重叠 | 等级、波次、提示条抢同一块区域。顶部 HUD 84 → 67px，等级并入左上，波次信息合并 |
| 摇杆和手指对不上 | `#stick` 容器 `position:absolute`，原点偏在 `42vh` 处，圆盘画到手指下方。整层视觉删除，输入本来走 canvas pointer，不受影响 |
| 升级卡斜条纹压字 | 伪元素默认画在内容之上，颜色又和字一样深。退到文字下层并改白色高光 |
| 后期越炸越晃 | 震屏纯线性累加，后期事件密度翻五倍。改成同批事件边际递减 |

### v0.13 · 第二批真机反馈

- BGM 再加长：战斗 52 小节 / 93.1 秒，BOSS 32 小节 / 50.5 秒。v0.12 的 57.3 秒高潮刚抬起来就转弱。
- 地刺从「身后撒」改成「目标脚下布设 + 减速」。
- 激光黄 → 红（为和青白箭矢分开）。
- 手机上特殊技能按钮移到右下，拇指够得到。

### v0.14 · 开始界面重做

- 激光红 → 石蓝 `#4a7fb8`。红色分得开，但在粉蓝地面上明度太高，像通电的灯管。新色从围墙石头六色里取，压暗降饱和，四个候选都真渲染出来比过。
- 新增 `inkOn(hex)`：按相对亮度在黑白两种墨水之间选。所有「用武器色当底」的地方直接复用。
- 开始界面从「两张卡片并排」改成「整屏被一条斜切光带分成两块」。旧模型的问题是盒子并排，屏幕一矮两个盒子一起缩，只能靠三层媒体查询硬补。
- 静音统一到右上角（桌面原来在 `left:12 top:72`，压在战斗视野里）。

## 五、两个仓库

| 仓库 | 可见性 | 放什么 | 谁在用 |
|---|---|---|---|
| `Karry-2026/pow-archer` | 私有 | 全部源码、文档、测试、截图、git 历史 | 开发 |
| `Karry-2026/pow-archer-play` | 公开 | 只有 `index.html` + README | GitHub Pages，评审点开的就是这里 |

分开的原因：免费账号的 Pages 只支持公开仓库。公开仓库里的 `index.html` 和任何人按 F12 看到的内容完全一样，私有仓库保护的是开发过程、文档和提交历史。

**同步方式**：主仓库改完 `index.html` → 复制到部署仓库 → 提交 → Pages 一分钟内自动更新。没有自动脚本，因为只有这一个文件，加脚本的维护成本比手抄高。

**核对线上是不是最新**：打开在线地址，控制台执行

```js
document.querySelector('meta[name=app-version]').content
```

返回 `v0.14.1` 就说明线上是这一版。

## 六、发版流程

改完代码到线上生效，固定这九步，顺序不能换：

1. **改代码**，只动 `index.html`。
2. **跑全部测试**，全绿再往下：
   ```bash
   node tests/orient.test.mjs        # 方向判断 8 条
   node tests/orient-buttons.test.mjs # 遮罩按钮 12 条
   node tests/layout.test.mjs        # 六尺寸布局 24 项
   node tests/title.test.mjs         # 开始界面 6 尺寸 × 4 断言
   node tests/touch.test.mjs         # 触屏拖拽 4 条
   node tests/ult.test.mjs           # 超武必杀 9 条
   node tests/arch.test.mjs          # 流派构筑 7 条
   node tests/boss-phase.test.mjs    # BOSS 阶段
   node tests/audio-start.test.mjs   # 起播与循环
   node tests/cardpool.test.mjs      # 卡池概率（纯 Node，不用浏览器）
   python docs/tools/audit_numbers.py # 表 / 代码 / 文档三方对账（需要 openpyxl）
   python docs/tools/calc_curve.py    # EXPECTED_DPS 与武器参数自洽
   ```
   平衡另跑 `node tests/run-balance.mjs`，它自己起 8913 端口。
3. **截图归档** `screenshots/vXXX-*.png`，用 `tests/title-shots.mjs` 那类脚本批量出图，不手截。
4. **写 `docs/DEVLOG.md`**：根因、做法、验证三段，缺根因的条目不写。
5. **更新本文第三节版本表**，加一行；改第二节上方的当前状态。
6. **改 `index.html` 里的 `app-version` meta**。
7. **同步 `docs/开发文档.html`**：状态条数字、版本时间线、版本管理表。
8. **改 `README.md` 的当前状态表**（版本、规模、已测条数）。
9. **提交并打标签**：
   ```bash
   git add -A
   git commit -m "v0.15: <一句话>"
   git tag -a v0.15 -m "v0.15"
   git push origin main --tags
   ```
10. **同步部署仓库**：复制 `index.html` 过去，提交并推送，等一分钟验线上 `app-version`。

## 七、回滚

| 场景 | 做法 | 影响 |
|---|---|---|
| 线上某一版更好，想退回去 | 从部署仓库历史里检出旧 `index.html` 提交 | 只影响线上，主仓库不动 |
| 代码改坏了 | `git checkout v0.10 -- index.html` 取回那一版 | 工作区被覆盖，先 `git stash` 或先提交 |
| 想整体回到某一版继续开发 | `git switch -c hotfix v0.10` | 新建分支，不动 `main` |
| 只是想知道线上是哪版 | 控制台读 `app-version` | 只读 |

## 八、还没做的

1. **版本号没进界面**。只在 meta 里，玩家看不到。要露出来得在暂停面板加一行小字。
2. **没有自动同步脚本**。两个仓库之间靠手抄，只有一文件时划算，文件变多就该写。
3. **没有 CI**。测试全在本地跑，靠人记得。加 GitHub Actions 的成本是每次要装无头浏览器，收益是提交即验证 —— 值得做，但排在参赛之后。
4. **`v0.13` 没有独立标签**。要补只能改写历史，不值得。
